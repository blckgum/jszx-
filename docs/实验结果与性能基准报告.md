本报告汇总校内道路车人冲突监测与预警系统在干净代码提交 `b2a4e59`（`git.dirty = false`，全量单元测试 **365/365** 通过、0 跳过）上的离线算法消融、确定性物理场景回归、GPU/CPU 分阶段性能基准、三组已标定公开路侧示范视频运行统计以及全中文离线图表产物。所有数据均直接由仓库内置工具链在干净工作树下采集并落盘于 `runs/analysis/experiments/`（`runs/` 为本地忽略产物目录，详见第 6、7 节），确保可复现、可审计。

## 2. 算法消融实验结果

消融实验由 `python -m analysis.ablation --output runs/analysis/experiments/ablation.json` 生成，原始本地产物见 [ablation.json](../runs/analysis/experiments/ablation.json)。

### 2.1 透视噪声下直线变速测速对比（滑窗 EMA 对比 2D CA 卡尔曼）

实验设定：构造 `6.0 m x 24.0 m` 单应性道路（25 FPS，共 100 帧，前 8 帧预热，统计后 92 帧），车辆经历加速（`+3.5 m/s^2`，0–1.6 s）、匀速巡航（1.6–2.4 s）与制动（`-3.2 m/s^2`，2.4–4.0 s）三阶段，在像素平面注入高斯观测噪声（`sigma_u = 2.0 px`、`sigma_v = 3.0 px`，随机种子 42）；2D CA 卡尔曼（CA Kalman）接收经单应性雅可比传播的地面观测协方差 `obs_cov_m2`。

| 测速模型 | MAE (m/s) | MAE (km/h) | RMSE (m/s) | RMSE (km/h) | 最大误差 (m/s) | 最大误差 (km/h) | 平均相位滞后 (s) |
|---|---:|---:|---:|---:|---:|---:|---:|
| 滑窗 EMA（指数平滑） | 0.584885 | 2.1056 | 0.686658 | 2.4720 | 1.585341 | 5.7072 | 0.20 |
| 2D CA 卡尔曼（恒加速度） | 0.368759 | 1.3275 | 0.460652 | 1.6583 | 1.297063 | 4.6694 | 0.08 |
| 相对滑窗 EMA 改善幅度 | -36.95% | -36.95% | -32.91% | -32.91% | -18.18% | -18.18% | -60.00% |

结论：校验通过（`kalman_improves_mae = true`）。在非均匀透视噪声与加减速切换工况下，引入雅可比协方差传播的 2D CA 卡尔曼将测速 MAE 降低 36.95%、RMSE 降低 32.91%，并将动态响应相位滞后由 0.20 s 缩短至 0.08 s（降幅 60.00%）。

### 2.4 短时遮挡断轨缝合对比（关闭对比开启 TrackletStitcher）

实验设定：25 FPS、75 帧，第 25–39 帧（共 15 帧，0.60 s）发生遮挡并导致底层跟踪器 ID 由 1 切换为 2，真实车速 `8.0 m/s`（28.8 km/h），搭配 2D CA 卡尔曼、OBB-SSM 与事件防抖状态机（`confirm_frames=3`、`cooldown_frames=20`）。

| 模式 | 车辆唯一轨迹 ID 数 | ID 切换次数 | 缝合恢复次数 | 预警事件数 | 测速 MAE (m/s) | 测速 MAE (km/h) | 连续性校验 |
|---|---:|---:|---:|---:|---:|---:|---|
| 关闭断轨缝合（`unstitched`） | 2 | 1 | 0 | 2 | 0.370176 | 1.3326 | 未通过（断轨产生重复告警） |
| 开启断轨缝合（`stitched`） | 1 | 0 | 1 | 1 | 0.018011 | 0.0648 | 通过（`stitching_preserved_continuity = true`） |

结论：开启 `TrackletStitcher` 后，0.60 s 遮挡后的轨迹成功缝合回原规范 ID（1 次缝合），消除重复告警（2 次降至 1 次），并因避免重新冷启动使测速 MAE 降低 95.13%（`0.370176 -> 0.018011 m/s`）。

## 4. 分阶段性能基准测试（GPU 对比 CPU）

性能基准由 `analysis.benchmark` 在真实路侧视频 `data/demo_videos/sherbrooke_intersection.mp4`（`800 x 600`、30.0 FPS）与非合成实测标定 `data/demo_videos/calib_sherbrooke_intersection.yaml`（`12.0 m x 10.5 m`、非合成标记 `synthetic: false`）上采集，统一启用完整算法链路：

- 推理配置：`yolov8n.pt`、`imgsz = 640`（`analysis.benchmark` 默认推理尺寸）、`bytetrack.yaml`、`object_policy.yaml`
- 算法配置：`--speed-model ctrv --conflict-model obb_ssm --enable-stitching --include-cyclist-vru`
- 渲染配置：默认开启标注视频渲染与写盘（`render_video = true`），完整计入逐帧开销

> 吞吐与分位数口径严格区分（避免混用冷启动全样本与剔除预热后的稳态统计）：
> 1. **帧内处理吞吐（`frame_processing_fps` / `end_to_end_fps`）**：按全部 `N` 帧的逐帧处理耗时之和计算（`1000 * N / sum(total_frame_ms)`），**不含**一次性模型加载耗时，但**包含**第 0 帧冷启动预热尖峰。对应全样本分阶段统计 `stages`（表 4.2）。
> 2. **稳态吞吐（`steady_state.steady_state_fps`）**：显式剔除首帧预热（`warmup_frames_excluded = 1`，仅评估后 `N - 1` 帧：GPU 119 帧、CPU 59 帧）后按稳态帧耗时之和计算。对应稳态分阶段统计 `steady_state.stages`（表 4.3），其均值、P50、P95、峰值与阶段占比均严格基于剔除首帧后的稳态切片。
> 3. **含模型加载墙钟吞吐（`wall_fps`）**：按全流程墙钟耗时计算（`N / (wall_elapsed_ms / 1000)`），完整计入模型加载（`model_load_ms`）、首帧预热与收尾资源封装开销。

原始本地 JSON 结果见 [benchmark_gpu.json](../runs/analysis/experiments/benchmark_gpu.json) 与 [benchmark_cpu.json](../runs/analysis/experiments/benchmark_cpu.json)。

### 4.4 性能瓶颈与冷启动分析

1. **三类吞吐差异与首帧冷启动摊薄效应**：
   - 在 GPU 120 帧基准中，第 0 帧 CUDA/cuDNN 内核初始化尖峰达到 `detect_track.max_ms = 2291.020 ms`（`total_frame.max_ms = 2339.880 ms`，约占 120 帧总帧耗时 `4008.84 ms` 的 `58.4%`）。因此全样本帧内处理吞吐 `frame_processing_fps = 29.934 FPS`、叠加上 `1254.827 ms` 模型加载后的墙钟吞吐 `wall_fps = 22.720 FPS`，均显著低于显式剔除首帧预热（`warmup_frames_excluded = 1`）后的稳态吞吐 `steady_state_fps = 71.304 FPS`（后 119 帧稳态单帧均值 `14.024 ms`、P50 `13.750 ms`、P95 `15.996 ms`、峰值仅 `19.248 ms`）。
   - CPU 60 帧基准呈现相同规律：首帧初始化尖峰为 `detect_track.max_ms = 1050.884 ms`（`total_frame.max_ms = 1101.789 ms`），全样本帧内处理吞吐 `17.328 FPS`、墙钟吞吐 `12.500 FPS`，剔除首帧后的 59 帧稳态吞吐为 `24.992 FPS`（稳态单帧均值 `40.014 ms`、P50 `39.897 ms`、P95 `45.102 ms`、峰值 `45.650 ms`）。
   - 第 5 节三组 360 帧独立进程示范运行采用更高推理分辨率 `imgsz = 960`（且 `summary.json` 的 `average_fps` 包含各自进程的首帧 CUDA 预热与收尾写盘，不含初始模型加载），实测平均帧内处理吞吐为 `34.4–41.5 FPS`，与上述分辨率及预热摊薄规律一致。
2. **检测与跟踪仍是主瓶颈**：在剔除首帧预热的稳态统计下，`detect_track` 仍占据 GPU 单帧耗时的 `62.10%`（均值 `8.710 ms`、P50 `8.373 ms`）与 CPU 的 `82.62%`（均值 `33.060 ms`、P50 `32.882 ms`）；GPU 在检测与跟踪阶段的稳态加速比达 `3.80 倍`（均值）与 `3.93 倍`（P50），整帧稳态加速比达 `2.85 倍`（均值）与 `2.90 倍`（P50）。
3. **几何物理与冲突模块开销极低**：即便同时启用完整的 `弯道 CTRV + OBB-SSM + TrackletStitcher + 骑行者 VRU`，投影与测速（`geometry_speed`）和冲突与事件（`conflict_events`）两阶段合计稳态均值仅 `1.199 ms/帧`（GPU 稳态占比 `8.55%`；全样本均值合计 `1.257 ms/帧`，占比 `3.76%`）与 `1.737 ms/帧`（CPU 稳态占比 `4.34%`；全样本均值合计 `1.868 ms/帧`，占比 `3.23%`），不会成为实时部署的性能瓶颈。

  @{ Name = "rouen_crosswalk";         Margin = "1.0" },
  @{ Name = "stmarc_mixed_vru";        Margin = "1.0" }
)
foreach ($d in $demos) {
  $outDir = "runs/analysis/demo_$($d.Name)"
  if (Test-Path $outDir) { Remove-Item -Recurse -Force $outDir }
  $code = @"
from analysis.calibration import RoadCalibrator
from analysis.pipeline import ConflictPerceptionPipeline
cal = RoadCalibrator.from_yaml('data/demo_videos/calib_$($d.Name).yaml')
pipe = ConflictPerceptionPipeline(
    calibrator=cal,
    device='0',
    iou=0.65,
    imgsz=960,
    zone_margin_m=$($d.Margin),
    speed_model='ctrv',
    conflict_model='obb_ssm',
    enable_stitching=True,
    include_cyclist_vru=True,
    compensate_anchor_bias=True,
)
pipe.process_video(
    video_path='data/demo_videos/$($d.Name).mp4',
    output_dir='$outDir',
    show_window=False,
    max_frames=360,
)
"@
  $code | & $py -
  if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
  & $py -m analysis.schema --run $outDir
  if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
}

# 2. 离线参数与算法消融（零视频依赖）
& $py -m analysis.ablation --output runs/analysis/experiments/ablation.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

# 3. 12 组确定性物理冲突场景回归（零视频依赖）
& $py -m analysis.scenarios --output runs/analysis/experiments/scenarios.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

# 4. GPU 分阶段性能基准（120 帧，imgsz=640，完整 CTRV + OBB-SSM + 断轨缝合 + 骑行者 VRU）
& $py -m analysis.benchmark `
  --source data/demo_videos/sherbrooke_intersection.mp4 `
  --calib data/demo_videos/calib_sherbrooke_intersection.yaml `
  --device 0 --max-frames 120 `
  --speed-model ctrv --conflict-model obb_ssm --enable-stitching --include-cyclist-vru `
  --output runs/analysis/experiments/benchmark_gpu.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

# 5. CPU 基线分阶段性能基准（60 帧，同算法配置）
& $py -m analysis.benchmark `
  --source data/demo_videos/sherbrooke_intersection.mp4 `
  --calib data/demo_videos/calib_sherbrooke_intersection.yaml `
  --device cpu --max-frames 60 `
  --speed-model ctrv --conflict-model obb_ssm --enable-stitching --include-cyclist-vru `
  --output runs/analysis/experiments/benchmark_cpu.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

# 6. 三组已标定示范运行契约校验与中文描述性评价
foreach ($name in @("sherbrooke_intersection", "rouen_crosswalk", "stmarc_mixed_vru")) {
  & $py -m analysis.evaluate `
    --run "runs/analysis/demo_$name" --validate --markdown `
    --output "runs/analysis/experiments/eval_$name.md"
  if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
}

# 7. 离线无界面中文 PNG 图表导出
& $py -m analysis.charts `
  --ablation runs/analysis/experiments/ablation.json `
  --run runs/analysis/demo_sherbrooke_intersection `
  --benchmark runs/analysis/experiments/benchmark_gpu.json `
  --output-dir runs/analysis/experiments/charts
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
