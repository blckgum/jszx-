# 原有图像分类实验：PyTorch、SimpleCNN 与 ResNet18

本文解释仓库根目录的分类学习流程，配合中文源码注释阅读。内容依据 `a31c390` 中的实现核对；它与校园道路的 YOLOv8 检测、ByteTrack 跟踪是两套独立入口。

分类模块已有数据加载、模型、训练、验证测试、检查点保存和推理代码；本文将“实现了流程”与“获得了真实数据成绩”分开描述。离线合成数据只用于功能检查，不提供 CIFAR-10 或校园交通效果结论。

## 1. 目标、入口与文件职责

分类回答“一张图属于哪一类”，输出整图的类别分数。检测则输出多个目标的框，跟踪还需要跨帧身份。即使 CIFAR-10 中包含 automobile、truck，分类模型也不能直接用于多车定位或车辆计数。

| 文件 | 主要接口 | 职责 |
|---|---|---|
| [`config.py`](../../config.py) | 常量配置 | 类别、32×32 尺寸、增强、训练超参数和固定输出路径 |
| [`common.py`](../../common.py) | `get_device()`、`set_seed()`、`AverageMeter` | 设备选择、随机源、样本加权均值、计时与环境提示 |
| [`dataset.py`](../../dataset.py) | `build_dataloaders()`、`SyntheticDataset` | CIFAR-10 / 合成数据、数据划分、增强及批处理 |
| [`model.py`](../../model.py) | `ConvBlock`、`SimpleCNN`、`build_model()` | CNN 结构、初始化、可选 ResNet18 |
| [`train.py`](../../train.py) | `train_one_epoch()`、`evaluate()`、`main()` | 梯度更新、验证、选模、保存及最终测试 |
| [`predict.py`](../../predict.py) | `load_model()`、`predict_image()` | 重建模型、预处理、Softmax 与 Top-K |

推荐按配置 → 数据 → 模型 → 训练 → 推理阅读。YOLO 使用 `python -m detection`，ByteTrack 使用 `python -m tracking`，无需先运行分类训练。

## 2. 数据怎样进入网络

### 2.1 Dataset 与 DataLoader

`Dataset.__getitem__(i)` 返回第 i 个 `(image, label)`；`DataLoader` 将多个样本堆成一批。当前分类输入约定如下：

| 数据 | 类型 / 形状 | 含义 |
|---|---|---|
| 单张图片 | float 张量 `[3,32,32]` | RGB，通道优先 |
| 一批图片 | float 张量 `[N,3,32,32]` | N 是实际批大小 |
| 一批标签 | 整型张量 `[N]` | 类别下标，默认 0～9 |
| 网络输出 | float 张量 `[N,10]` | 每张图的 10 个 logits |

N 不必等于配置的 `BATCH_SIZE`：验证和测试最后一批可能更小。训练使用 `drop_last=True` 丢弃不足一批的末批，因此批大小大于训练集长度会使这一轮没有训练批次。

`shuffle=True` 只用于训练；`num_workers=0` 表示主进程加载数据。Windows 也可使用正确配置的多进程，当前选择 0 是为了减少入门配置差异。`pin_memory` 仅在 CUDA 可用时开启。

### 2.2 真实数据与增强

CIFAR-10 图片原本就是 32×32 RGB。训练依次使用随机裁剪、水平翻转、旋转、颜色抖动、`ToTensor()` 与 `Normalize()`；验证和测试只使用后两个确定性操作。

`ToTensor()` 将常见 PIL RGB 图片转换为 `[C,H,W]` 的浮点张量，像素从 0～255 缩放到 0～1。随后逐通道计算：

```text
x_normalized = (x / 255 - mean[channel]) / std[channel]
```

这里公式中的 x 指原始整数像素；在代码中除以 255 已由 `ToTensor()` 完成。`Normalize` 后数值可以小于 0 或大于 1。均值、标准差来自配置中的 CIFAR-10 统计量，不表示每张图都会恰好变为均值 0、标准差 1。

默认将 CIFAR-10 官方训练集的 50,000 张划成 45,000 训练、5,000 验证，官方 10,000 张测试图保持独立。两个训练集视图读取相同原始文件，但使用互不重叠的下标：训练视图带增强，验证视图不带增强。没有从测试集抽取验证样本。

### 2.3 离线合成数据的用途

`--fake` 使用 `SyntheticDataset(size=5000)`，按固定随机划分得到 3,000 / 1,000 / 1,000 个训练、验证、测试样本。图片已是 `[3,32,32]` 张量，直接使用，**跳过整套增强和标准化**。

合成图在左上 8×8 区域植入与类别有关的颜色规律。它适合检查能否读取批次、计算损失、反传、保存与重载模型；其准确率不能外推到真实图片。表现不好也应结合训练轮数和输入分布排查，而不是仅凭某个分数判断流程一定正确或错误。

`set_seed()` 设置多个随机源以减少差异，但不会保证跨设备、库版本完全一致。当前函数在进程内设置 `PYTHONHASHSEED`，不能回溯改变本进程启动时已确定的哈希随机化。

## 3. 模型如何把图像变为类别分数

### 3.1 SimpleCNN 的实际张量形状

每个 `ConvBlock` 为 3×3 Conv → BatchNorm → ReLU；每阶段有两个块，再接一次池化：

| 步骤 | 输出形状 | 作用 |
|---|---|---|
| 输入 | `[N,3,32,32]` | RGB 图片 |
| 两个卷积块，32 通道；MaxPool | `[N,32,16,16]` | 提取局部特征并下采样 |
| 两个卷积块，64 通道；MaxPool | `[N,64,8,8]` | 增加通道并扩大感受范围 |
| 两个卷积块，128 通道；MaxPool | `[N,128,4,4]` | 形成更高层特征 |
| AdaptiveAvgPool2d(1) | `[N,128,1,1]` | 每个通道在空间上求均值 |
| Flatten、Dropout | `[N,128]` | 展平；训练时随机屏蔽部分特征 |
| Linear(128,10) | `[N,10]` | 输出类别原始分数 |

卷积的 `kernel_size=3, stride=1, padding=1` 保持空间尺寸，MaxPool 再减半。BatchNorm 按通道使用批次及空间位置的统计量，带有可学习的缩放和平移；它不是保证每层所有输出永远符合标准正态分布。

AdaptiveAvgPool 能适应不同大小的剩余特征图，但前面的三次池化仍要求输入空间尺寸足够大；它不表示任意大小、任意通道数的输入都合法。

### 3.2 ResNet18 与迁移学习

`build_model("ResNet18")` 构造 torchvision 的 ResNet18，并将最后的 `fc` 替换成输出 `num_classes` 个分数的层。`config.USE_PRETRAINED=False` 是当前默认值；设为 True 才使用 ImageNet 预训练权重，首次可能需要下载。

当前代码没有冻结主干，训练器将所有模型参数交给 AdamW，因此会一起优化。代码未自动把 32×32 数据改成 ImageNet 尺寸或统计量；若研究迁移效果，需要另行统一训练、验证及推理预处理并进行实测。

## 4. 一个训练批次经历什么

设一批有 N 张图，标签 `y[i]` 是正确类别下标，输出 `z[i,c]` 是该类别的 logit。交叉熵可写为：

```text
loss_i = -z[i, y[i]] + log(sum(exp(z[i, c]) for c in classes))
loss = mean(loss_i)
```

实际使用 `nn.CrossEntropyLoss()` 的稳定数值实现，不在代码里直接计算上述指数。训练时直接传 logits；先做 Softmax 会改变损失的输入含义。

`train_one_epoch()` 对每批依次执行：

1. `model.train()` 已切换训练模式，将图片与标签搬到同一设备。
2. `optimizer.zero_grad()` 清空上一批梯度，避免意外累加。
3. `model(images)` 前向计算 logits，`criterion(outputs, labels)` 得到损失。
4. `loss.backward()` 按链式法则计算参数梯度；这一步尚未更新权重。
5. `clip_grad_norm_(..., 1.0)` 限制总体梯度范数，再由 `optimizer.step()` 更新参数。

AdamW 使用自适应梯度统计，并将权重衰减与梯度更新解耦；不能简单等同于把 L2 正则项加到损失中。余弦调度器在每轮训练、验证结束后调用 `scheduler.step()`。

平均损失按样本数加权。例如一批 128 张均值损失 0.5，另一批 32 张均值损失 1.0，总均值为 `(128×0.5+32×1.0)/160=0.6`，而不是两个批均值直接平均得到 0.75。`AverageMeter` 用于保留这个口径。

## 5. 验证、选模与续训的实际规则

`evaluate()` 同时使用 `model.eval()` 和 `@torch.no_grad()`：前者切换 BatchNorm/Dropout 行为，后者关闭梯度记录，两者作用不同。它不调用 `optimizer.step()`。

准确率为 `100 × 预测正确数 / 样本总数`，代码返回百分数。保存 `best.pt` 的依据是 **val_acc 严格提高**；并非选择 val_loss 最小的模型。

当前早停实现结合两个条件：本轮 val_loss 高于此前最小值，同时验证准确率连续未提高的轮数达到 patience。准确率计数在提高时清零。这与“只监视 loss 并连续计数”的早停不同，源码中的判断表达式应作为实际依据。

训练结束重新载入 best 权重，运行测试集并保存历史。测试结果用于最终评价；如果反复根据它改参数，会削弱独立评估的意义。

`--resume` 恢复模型状态、优化器状态和轮号，但目前不恢复调度器状态、随机状态、历史曲线、早停计数和历史最佳值。它支持继续优化，不能保证复现不中断训练的过程；续训时模型结构、类别数量等也要与检查点一致。`--epochs` 表示总目标轮数，需大于已完成轮数才会进入后续训练循环。

## 6. 推理与检查点

分类检查点保存 `model_state`、`model_name`、`class_names` 等元数据。`predict.load_model()` 先根据名称与类别数重建结构，再载入权重并执行 `eval()`。

`predict_image()` 的两条输入路径要分清：

- 图片路径：PIL 读图并转 RGB → Resize 到配置尺寸 → ToTensor → CIFAR-10 Normalize。
- 已处理张量：直接使用调用者传入的张量，函数不再缩放或标准化。

随后 `unsqueeze(0)` 加上批次维度，得到 `[1,3,32,32]`；模型输出 `[1,10]`，推理时再用 `softmax(dim=1)` 转成类间归一化分数，`topk` 取最大的 K 项，并用检查点中的类别名映射下标。

Softmax 分数总和为 1，不代表模型具备识别“未知类”的能力，也不保证分数经过正确率校准。`--demo` 的随机张量可能产生很高分数；它只展示推理接口，既不是带植入规律的合成测试图，也不是可信的交通样本。

分类检查点的字典结构与 Ultralytics 的检测权重接口不同。不要把根目录 `checkpoints/best.pt` 直接作为 YOLO 检测权重使用，反之亦然。

## 7. 运行与产物

在已安装匹配 torch、torchvision 及项目依赖的环境中，从仓库根目录运行：

```bash
# 环境与形状检查，不需要训练数据
python common.py
python model.py
python train.py --help
python predict.py --help

# 离线流程演示；会写入固定分类产物路径
python train.py --fake --model SimpleCNN --epochs 1 --batch-size 128
python predict.py --ckpt checkpoints/best.pt --demo

# 真实 CIFAR-10；首次可能下载数据，轮数需按实验设计决定
python train.py --model SimpleCNN --epochs 30

# 将图片路径换成实际文件，使用与训练数据语义对应的检查点
python predict.py --ckpt checkpoints/best.pt --image path/to/image.jpg
```

一轮离线运行用于验证流程，不能据此评价模型已学充分。`get_device()` 按 CUDA → MPS → CPU 选择设备，当前分类 CLI 没有检测入口的 `--device` 参数。

| 产物 | 内容与注意事项 |
|---|---|
| `checkpoints/best.pt` | 按验证准确率选出的分类检查点，含类别名称与模型状态 |
| `checkpoints/last.pt` | 最近完成轮次的检查点，可用于继续优化 |
| `runs/history.json` | 本次训练/验证历史、最终测试指标和命令参数 |
| `runs/training_curves.png` | Matplotlib 可用时生成的曲线 |

这些是固定路径，后续运行会覆盖同名产物；做对比实验前应先另存旧结果。检测和跟踪入口的 `new_run()` 则要求独立目录。源码中的文件路径均从项目配置获得，笔记中的 `path/to/...` 需要替换。

## 8. 易错点与验证边界

| 现象 / 误解 | 解释与检查位置 |
|---|---|
| 合成数据分数高，真实照片却预测错误 | 训练分布与图片预处理不同；先核对 `build_dataloaders()` 和 `predict_image()` 两条输入路径 |
| 同图预测每次不同 | 检查是否 `eval()`、是否错误地使用随机增强；关闭梯度本身不会关闭 Dropout |
| 改类别后无法载入模型 | 核对检查点 `class_names`、模型名称和最终层维度 |
| 改根目录 config 却不影响 YOLO | 两套入口独立，YOLO 使用命令参数和数据 YAML |
| 续训曲线或学习率不连续 | 目前没有完整恢复调度、历史和随机状态，见第 5 节 |
| 把 fake 或随机张量分数写成实景结果 | 功能样例只用于执行检查；真实评价需要独立真实数据 |

现有 `tests/` 主要覆盖检测与跟踪，不是分类精度测试。分类可分层核对：`python model.py` 检查形状；小批量离线训练检查前向/反向及评估；保存后重载检查类别映射和预测一致性；最后再用真实独立数据评价准确率。前几项通过仍不能推出模型的真实泛化效果。本轮已完成小批量接口检查，具体范围与实际结果见[交付核验记录](README.md#6-本轮文档交付核验记录)。
