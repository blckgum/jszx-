# 课题需求与技术路线

## 1. 项目定位

暂定题目：**基于视觉目标检测与多目标跟踪的校园道路行人冲突感知与车速预警系统**。

本文依据项目负责人提供的课题规划整理，作为后续开发的需求依据。主要场景是校园道路固定路侧摄像头，目标是感知车辆与行人、估计车辆速度、分析双方潜在冲突，并向驾驶员及路旁学生提示风险。

当前已具备 YOLOv8 检测和独立的 ByteTrack 无界面跟踪模块，支持本地视频/目录、ID 与轨迹、逐目标 CSV、生命周期事件、运行汇总及构造样例验证。接下来完善校园场景数据与跟踪验收，再开展标定测速，最后研究冲突分析与 TTC 并集成展示。当前没有新增测速或预警决策代码。

## 2. 完整链路与阶段交付

| 顺序 | 环节 | 方法与工具 | 可验收交付 |
|---|---|---|---|
| 1 | 视频采集与数据集构建 | 固定路侧摄像头、校园自采视频；BDD100K 等公开数据作为候选补充；OpenCV、FFmpeg、CVAT | 场景说明、视频片段清单、数据来源与采集条件 |
| 2 | 预处理与标注 | 视频抽帧、质量筛选、CVAT 框标注、YOLO 格式转换、分组划分数据 | 训练/验证/测试集及类别映射，避免同一视频相邻帧跨集合 |
| 3 | 车辆与行人检测 | YOLOv8 + PyTorch | 类别、置信度、检测框，分项指标与漏检/误检样例 |
| 4 | 多目标跟踪 | ByteTrack、Kalman Filter、基于 IoU 的关联与线性分配 | 稳定 ID、连续位置、历史轨迹及跟踪评价 |
| 5 | 摄像机标定与运动估计 | OpenCV、畸变校正、透视/单应性变换、位移/时间与滤波 | 道路坐标、方向、速度及误差评估 |
| 6 | 轨迹预测与冲突分析 | 匀速模型、速度向量、短时外推、冲突区域几何判断 | 潜在冲突对象、区域和预计占用时段 |
| 7 | TTC 与风险决策 | TTC 适用条件判断、到达时间差、风险分级、独立限速判断 | 正常 / 注意 / 高风险，以及独立超速提醒 |
| 8 | 实时预警与 Demo | OpenCV 实时画面；Streamlit / FastAPI 可选展示或接口层 | 驾驶员提示、路旁学生提示、危险事件记录与可复现演示 |
| 9 | 实验与论文材料 | 检测、跟踪、速度和预警事件评价；Pandas、Matplotlib、scikit-learn 等按需使用 | 实验报告、论文图表、PPT、答辩材料 |

第 5～7 步是研究重点。YOLOv8、ByteTrack 的感知结果需要经过标定、运动估计及冲突建模，才能用于实际速度和风险计算。

## 3. 检测阶段的需求边界

已经提供 YOLOv8n 预训练检测、图片/目录/视频输入、原图坐标与逐帧时间信息导出、训练和评估入口。校园数据上的微调、模型对比与独立测试仍待开展。

当前保留 person、bicycle、car、motorcycle、bus、truck 六个细分类，并在导出时增加 pedestrian / vehicle 分组。正式数据准备时确定最终类别，骑行者是否作为独立风险对象需在标注与评价口径中统一。

阶段交付顺序：

1. 收集与演示机位一致的视频或图片，确认行人、车辆、遮挡、夜间、远距离目标等场景覆盖。
2. 固定类别映射与数据划分，优先以校园实景验证固定机位任务；公开车载数据存在视角差异。
3. 训练 YOLOv8n 基线，在相同划分上按需对比 YOLOv8s，记录 Precision、Recall、mAP50 和 mAP50-95。
4. 分析漏检与误检，尤其是横穿行人、小目标和遮挡；依据实验决定数据补充或算法改进。
5. 固定导出接口，为 ByteTrack 保留时间、细分类及足够的低置信度候选框。

## 4. 跟踪与状态估计

ByteTrack 的 Kalman 预测、分阶段关联和轨迹管理作为完整流程接入。使用线性分配求解关联问题，结合场景调整检测及匹配阈值，重点测试目标交叉、遮挡、重新出现时的 ID 稳定性。

检测阶段的 `track_id` 为 null；已接入的 tracking 入口生成连续目标 ID 与独立会话标识，见 [跟踪解释文档](modules/02_多目标跟踪_ByteTrack_解释文档.md)。像素坐标中的 Kalman 速度不是实际道路速度，实际速度需转换到米制道路坐标后估计。

## 5. 摄像机标定与测速

固定摄像头优先采用近似道路平面模型。选取至少四组非共线的图像点与已知道路平面点，估计图像到道路的单应性矩阵；镜头畸变应先处理。地面接触点可先以检测框底边中心近似，需评估遮挡、车辆尺寸和接触点偏差。

$$
\lambda\begin{bmatrix}X\\Y\\1\end{bmatrix}
=H\begin{bmatrix}u\\v\\1\end{bmatrix}
$$

其中 `(u,v)` 为图像点，`(X,Y)` 为道路上的米制坐标。轨迹平滑后，利用时间窗口内的道路位移计算速度，并将 m/s 乘以 3.6 转为 km/h。

实验需要参考速度或具有已知距离与时间的测试过程，比较不同道路位置和距离下的测速 MAE、RMSE。道路非平面、相机抖动、遮挡及不可靠时间戳应纳入适用条件说明。

## 6. 冲突预测、TTC 与限速

第一版采用短时匀速模型：

$$
\hat{\mathbf{p}}(t+\tau)=\mathbf{p}(t)+\mathbf{v}(t)\tau.
$$

冲突分析同时考虑目标的空间范围、进入冲突区域的预计时间和占用时段。两条轨迹在二维平面相交并不足以说明双方会发生冲突，还需比较到达时刻及空间安全余量。

对于距离与接近方向明确的简化场景，可估计 `TTC = 距离 / 接近速度`；不存在有效接近或冲突条件时，不应强行输出正的碰撞时间。车辆与横穿行人的主要分析对象是冲突区域到达时间差、相对位置和轨迹不确定性，再据此形成正常、注意、高风险的解释规则。

初始限速参数为 **30 km/h**。超速判断与冲突风险分别输出：

- 未超过 30 km/h 的车辆仍可能与横穿行人产生高风险。
- 超过限速但当前没有冲突对象时，仍可产生超速提醒。
- 测速容差、时间窗口、报警持续时间和阈值回滞需通过实际数据设定；本阶段不预设未经验证的风险阈值。

## 7. 硬件与展示安排

计划使用 RTX 5060 执行 YOLOv8 训练与检测，CPU 执行视频处理、跟踪及几何计算；部署时根据实测性能调整任务分配。当前云机器无 GPU，尚未验证 RTX 5060 上的吞吐量和完整系统延迟。

第一版优先完成同一台机器上的视频输入、检测跟踪、测速、风险判断和 OpenCV 画面展示。之后按演示需要选择 Streamlit 或 FastAPI，扩展提示与事件记录。TensorRT、复杂 3D 感知和多传感器融合不属于第一版必须内容。

## 8. 实验与剩余输入

| 评价维度 | 建议指标或参考数据 |
|---|---|
| 检测 | Precision、Recall、mAP50、mAP50-95；场景及类别分项 |
| 跟踪 | IDF1、HOTA、ID 切换数量；带连续 ID 标注的视频 |
| 测速 | MAE、RMSE；参考速度、距离与计时信息 |
| 风险识别 | 事件级召回、误报率、预警提前量；有冲突事件和正常通行事件的视频 |
| 实时系统 | 处理吞吐量、端到端延迟、危险事件日志完整性 |

仍需准备：校园道路原始视频与机位信息、检测标注、标定参考点及实际道路尺寸；跟踪和预警阶段继续补充目标 ID、参考速度与事件标注。具体精度目标及可接受延迟尚未给定，应在建立实景基线后确定。
