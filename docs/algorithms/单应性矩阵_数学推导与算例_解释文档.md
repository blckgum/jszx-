# 单应性矩阵：数学推导与算例解释文档

本文集中解释算法原理。配置、命令、输出和实测准备见[标定模块解释文档](../modules/04_摄像头标定与道路坐标映射_解释文档.md)。实现位于 `calibration/`，原有 `analysis/` 四点路径保留。

## 1. 它是不是 Tensor 算法

**这里的算法名称是单应性估计与射影变换，不是“Tensor 算法”。** 矩阵可以视为二阶张量，也能放进 PyTorch Tensor 运算；使用张量这种数据表示，不会把它变成一个需要训练的神经网络。

| 概念 | 含义 | 在项目中的角色 |
|---|---|---|
| Tensor / 张量 | 标量、向量、矩阵和更高维数组的统一表示 | PyTorch 网络输入与计算中常用 |
| PyTorch | 支持张量、自动求导、神经网络训练的框架 | 执行 YOLOv8 等模型 |
| TensorRT | NVIDIA 推理优化与部署工具 | 当前标定模块未使用，不是标定算法 |
| Homography / 单应性 | 两个平面坐标之间的射影关系 | 将道路接地点由图像映射到道路平面 |
| OpenCV / NumPy | 视觉算法、线性代数与数组工具 | 本模块求解、去畸变、投影和数值检查 |

因此本模块不需要训练数据集、反向传播、损失函数或 GPU。它需要的是**同一物理参考点的像素位置与地面坐标**。

## 2. 图像坐标与道路坐标为什么不同

图像点记为 `(u,v)`：原点通常在左上角，u 向右、v 向下，单位 px。道路平面点记为 `(X,Y)`：原点和轴方向由测量者定义，单位 m。

斜视摄像头产生透视：远处一米和近处一米在画面里占用的像素不同，不能给所有像素位移乘一个统一的“米/像素”比例。单应性用一个带有齐次除法的矩阵关系描述这种变化。

本项目使用框底边中心作为接地点近似：

```text
u = (x1 + x2) / 2
v = y2
```

框中心通常在人体或车身内部，不能直接当作道路平面点。底边中心也不是精确物理接触点；遮挡、车身形状和框定位误差仍会影响后续运动估计。

## 3. 从针孔相机模型得到平面单应性

理想针孔模型中，三维世界点的成像关系为：

\[
s\begin{bmatrix}u\\v\\1\end{bmatrix}
=K\,[R\mid t]
\begin{bmatrix}X\\Y\\Z\\1\end{bmatrix}.
\]

`K` 是相机内参，包含焦距和主点；`R,t` 描述相机与世界坐标系的旋转和平移。这是**不含镜头畸变的理想成像关系**。

如果选定道路近似满足 `Z=0`，三维投影可化为：

\[
s\begin{bmatrix}u\\v\\1\end{bmatrix}
=K[r_1\;r_2\;t]
\begin{bmatrix}X\\Y\\1\end{bmatrix}
=H_{g\to i}\begin{bmatrix}X\\Y\\1\end{bmatrix}.
\]

只要矩阵可逆：

\[
\lambda\begin{bmatrix}X\\Y\\1\end{bmatrix}
=H_{i\to g}\begin{bmatrix}u\\v\\1\end{bmatrix},
\qquad H_{i\to g}=H_{g\to i}^{-1}.
\]

本模块变量 `H`、产物 `image_to_ground_h` 都表示 **图像→地面**；`H_inv`、`ground_to_image_h` 表示反向。明确方向比单独写一个 H 更重要。

通过平面对应点可以直接估计 H，不必先分别恢复 K、R、t；但这种做法不自动消除镜头畸变，也不适用于任意非平面空间中的目标位置。

## 4. 齐次坐标与透视除法

令：

\[
\begin{bmatrix}a\\b\\c\end{bmatrix}
=\begin{bmatrix}
h_{11}&h_{12}&h_{13}\\h_{21}&h_{22}&h_{23}\\h_{31}&h_{32}&h_{33}
\end{bmatrix}
\begin{bmatrix}u\\v\\1\end{bmatrix}.
\]

最终坐标不是 `(a,b)`，而是：

\[
X=\frac{a}{c}=\frac{h_{11}u+h_{12}v+h_{13}}{h_{31}u+h_{32}v+h_{33}},\quad
Y=\frac{b}{c}=\frac{h_{21}u+h_{22}v+h_{23}}{h_{31}u+h_{32}v+h_{33}}.
\]

分母随图像位置变化，正是它产生了位置相关的透视尺度。如果分母接近零，点接近投影无穷远，不能把分母硬夹成一个小数，也不能将结果写成 `(0,0)`。

H 与任意非零倍数的 H 描述相同投影。代码先归一化整体尺度，再进行相对分母检查。普通点调用 `cv2.perspectiveTransform()`；接近该 API 内部绝对分母阈值但仍通过相对数值检查的点，显式做齐次除法，避免它们被库返回为假零点。

有些教材设置 `h33=1` 便于推导，但不是所有有效 H 都满足 `h33!=0`。实现没有把它当作必需条件。

## 5. 为什么最少需要四组对应点

H 有九个元素，整体比例无关，所以有八个自由度。一组对应点 `(u,v) ↔ (X,Y)` 提供两条约束：

\[
u h_{11}+v h_{12}+h_{13}-Xu h_{31}-Xv h_{32}-Xh_{33}=0,
\]
\[
u h_{21}+v h_{22}+h_{23}-Yu h_{31}-Yv h_{32}-Yh_{33}=0.
\]

每组点可写成矩阵中的两行：

```text
[u v 1  0 0 0  -Xu -Xv -X]
[0 0 0  u v 1  -Yu -Yv -Y]
```

将所有点堆叠得到 `A h = 0`，其中 h 是 H 的九个元素排列成的向量。这就是 DLT（Direct Linear Transform）的基本形式。

通常先对坐标做归一化，改善像素和米的尺度差异，再通过 SVD 求满足约束的非零解，并反归一化。当前项目**使用 OpenCV 的求解与优化实现**，没有重新实现一套 DLT/SVD 求解器。

四组点只有在几何分布非退化时才够用。四点情形不能有重复点、三点共线或对应关系错误。多点情形允许路面网格中部分点共线，但整体仍须覆盖二维区域。

通用模式按同一物理点一一配对，不要求把所有点排成“左上、右上”。只有旧版四点矩形便利模式要求四角沿边界一致顺序对应到 `(0,0)、(W,0)、(W,L)、(0,L)`。随意交换一边的对应顺序可能让投影无穷远穿过道路区域，代码会检查这种异常。

## 6. 多点拟合与 RANSAC

多于四组点时，一般无法让每组噪声观测都精确满足关系，可以用所有点进行拟合。少数点选错或地面坐标抄错时，RANSAC 会反复尝试小样本模型，按误差寻找一致内点，再进行估计。

本模块在 `method: ransac` 下要求至少五组点，以提供最低限度冗余；实际建议使用更多、分布均匀的点。五点并不等于稳健，四个内点也不能代替独立验证。

特别注意本接口方向为图像→地面：

```python
# 接口原理示意；image_points 是像素，ground_points 是米。
H, mask = cv2.findHomography(
    image_points,
    ground_points,
    method=cv2.RANSAC,
    ransacReprojThreshold=0.2,
)
```

这里阈值 0.2 的单位是 **m**，不是 px。配置名使用 `ransac_threshold_m`，避免直接复制其他像素域示例里的“3 像素”。这个默认值只是调试起点，不代表已经满足你的实测精度要求。

RANSAC 不能解决系统性测量错误、地面不平、所有对应点一起标错等问题。输出会记录内点掩码；默认 ROI 采用内点图像凸包，离群点不扩大有效范围。

## 7. 镜头畸变与 H 必须统一坐标系

针孔镜头常用径向和切向畸变描述。以简化五参数模型为例，归一化相机坐标 `(x,y)` 满足：

\[
r^2=x^2+y^2,\quad L=1+k_1r^2+k_2r^4+k_3r^6,
\]
\[
x_d=xL+2p_1xy+p_2(r^2+2x^2),
\]
\[
y_d=yL+p_1(r^2+2y^2)+2p_2xy.
\]

图像像素再由焦距和主点得到。实际 OpenCV 模型可包含更多参数，本模块接受其支持的 4/5/8/12/14 参数针孔模型；鱼眼需要另一套明确的模型，当前不接受混用。

本模块选择以下统一约定：

1. 配置中的图像参考点和跟踪接地点都来自**原图像素坐标**。
2. 有内参时，二者都经 `cv2.undistortPoints(..., P=K)` 转成去畸变像素坐标。
3. H 在该去畸变像素系中拟合，也在同一坐标系中应用。
4. 回画原图网格时，先通过 H 的逆映射回去畸变像素，再用镜头模型恢复原图位置。

`P=K` 是关键：省略 P 时，OpenCV 通常返回无量纲的归一化相机坐标，而不是像素。如果只给目标点去畸变，或把归一化坐标送进按像素拟合的 H，会得到错误位置。

当前固定的 OpenCV 5 在 `undistortPoints` 上直接提供 criteria 参数；本模块设置迭代条件，并通过正反向畸变数值测试检查一致性。

`lens: null` 代表未校正，不能解释成镜头不存在畸变。有需要时，后续应使用同一镜头、分辨率、焦距设置下多张不同姿态的棋盘格照片，通过 `calibrateCamera` 等流程取得 K 与畸变参数。本轮提供参数接入，没有凭合成数据完成你实际摄像头的内参标定。

## 8. 一个可以手算的例子

假设一个构造的正视矩形：图像范围 `(100,100)` 到 `(700,500)`，对应道路宽 6 m、长 20 m，则：

\[
H=\begin{bmatrix}0.01&0&-1\\0&0.05&-5\\0&0&1\end{bmatrix}.
\]

对图像点 `(400,300)`：

```text
a = 0.01×400 − 1 = 3
b = 0.05×300 − 5 = 10
c = 1
地面坐标 = (3 m, 10 m)
```

这个例子属于仿射特例，分母恒为 1。斜视道路通常有非零的 h31、h32，不能套用这里的固定比例。本模块的 demo 使用透视梯形，并用另外的地面检查点和轨迹点验证映射。

## 9. 为什么“拟合误差很小”仍然不够

恰好四点的模型通常能精确插值这四点，即使你把道路宽度填错，也可能看到近乎零的拟合残差。

应另选不参与求解的物理检查点。对第 i 个检查位置：

\[
e_i=\|\hat p_i-p_i^{ref}\|_2,
\quad \overline e=\frac1N\sum_i e_i,
\quad RMSE=\sqrt{\frac1N\sum_i e_i^2}.
\]

这里平均误差、RMSE、最大误差都以 **m** 为单位，是位置误差，不是速度误差。检查点须独立于拟合点、数量足够且分布展开。任何无效检查点都会让整次检查不通过，不通过删掉坏点来美化报告。

新接口中 `calibration_valid=true` 的含义是：配置声明实测来源，且满足当前代码的独立检查规则与配置阈值。代码无法自行认证测量记录的真实性，也不能仅凭少量检查点保证整个道路区域的准确性。

合成样例即使检查误差接近零，也始终保留 `synthetic=true`、`calibration_valid=false`。这只能证明数值流程正确，不能成为论文里的实景测速精度。

## 10. 从映射继续走向测速时

未来应对带源时间戳的地面位置使用滑动窗口位移，再计算 m/s 与 km/h。本轮不执行这一步。

通常先做像素→道路位置映射，再在道路坐标系估计运动；不能用“一个固定米/像素比例”换算所有 px/s。像素平滑与透视映射也不完全可交换，已经平滑的像素位置会带来额外滞后，因此接口默认保留并选用本模块输入前的跟踪接地点，只有显式选择时才使用平滑点。

道路凸起、坡度变化、相机晃动、裁剪和缩放、遮挡以及接地点误差都会影响结果。机位或像素坐标系改变时，需要重新核对标定；有已知图像变换时可以研究组合 H，本轮默认拒绝尺寸不匹配，避免静默沿用错误坐标系。
