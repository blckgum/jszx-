# 车辆与行人检测：当前实现和后续方案

目前可见的需求：先完成 YOLOv8 + PyTorch 行人车辆检测，再接 ByteTrack，最后研究运动状态与 TTC。当前对话和仓库未包含完整任务书，尚未指定数据集、硬性指标或摄像机视角。

## 阶段安排

| 阶段 | 主要工作 | 验收依据 |
|---|---|---|
| 1. 目标检测（本次重点） | YOLOv8n 预训练检测；图片/视频输入；类别筛选；标注数据训练及评估；逐帧结果导出 | 实际样例检测、视频完整输出；有标注数据上的 Precision、Recall、mAP50、mAP50-95 |
| 2. 多目标跟踪 | ByteTrack 的 Kalman 预测、高低置信检测关联、轨迹管理及线性分配匹配 | 有 ID 标注的视频上的 IDF1、HOTA、ID 切换数量，遮挡后轨迹表现 |
| 3. 动态分析与 TTC | 标定、轨迹平滑、运动状态估计、相对运动与风险决策 | 可核实的距离/速度误差、风险事件漏报与误报；固定机位和车载视频分开验证 |

ByteTrack 已包含卡尔曼预测及关联流程，先使用标准实现，不另写重复的跟踪器。OpenCV 在阶段 1 就用于视频解码、绘制和保存；放到后面的是运动分析。

## 仓库现状与本次新增

原有 `train.py`、`model.py`、`predict.py` 是 SimpleCNN / ResNet18 图像分类教学代码，继续保留。新增独立的 `detection/` 模块，避免混淆分类训练和目标检测训练。

```text
detection/
  __main__.py       # detect / train / val 命令
  core.py           # YOLOv8 加载、图片/视频检测、可视化及 JSONL 导出
  dataset.py        # 数据集路径、类别、标签及划分检查
configs/traffic.example.yaml
requirements-yolo.txt
tests/test_detection.py
```

基线选用 YOLOv8n，便于先跑通；后续在同一数据划分上对比 YOLOv8s。当前无 GPU，CPU 推理和小规模流程验证已可运行，正式训练建议使用 GPU。没有给出未经实测的实时 FPS 或准确率承诺。

本次验证：官方 bus 图片检出 1 辆公交车和 4 个行人；道路样例还检出了汽车、自行车和卡车。3 帧样例视频包含空白帧，逐帧导出、输出视频解码、帧数限制与 FPS 覆盖通过。COCO128 筛选并重映射后的 4 张训练图、4 张验证图完成 1 轮训练和独立验证，另 2 张不重叠图片验证了 test 入口；6 项回归测试通过。视频由静态样例拼接，未验证真实道路动态场景。单轮微调后的分数很低，这次验证只检查训练与评估流程，默认检测继续使用官方预训练权重。

## 安装与检测

云环境已经安装依赖、下载官方 YOLOv8n 权重，激活环境即可使用：

```bash
cd /workspace/jszx-
source /workspace/venvs/jszx/bin/activate

# 图片：首次自建环境运行时会下载官方权重，保存到 checkpoints/yolo/
python -m detection detect --source data/demo/bus.jpg --device cpu

# 图片目录：只扫描当前目录，不递归
python -m detection detect --source data/demo/images --device cpu

# 本地视频
python -m detection detect --source data/your_video.mp4 --device cpu

# 按类别筛选；CPU 调试时只处理前 100 帧
python -m detection detect --source data/your_video.mp4 \
  --classes person car bus truck --max-frames 100 --device cpu
```

新机器需要先安装匹配硬件的 PyTorch，再装新增依赖。下面是本云机器验证过的 CPU 安装方式：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.11.0 torchvision==0.26.0 \
  --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-yolo.txt
python -m pip check
```

RTX 50 系 GPU 的环境应使用匹配该 GPU 的 CUDA 版 PyTorch，不能照搬 CPU 安装命令。此处的 Ultralytics 版本号不是模型版本；使用的模型权重明确为 `yolov8n.pt`。

默认检测 `person / bicycle / car / motorcycle / bus / truck`。导出中将 `person` 归为 `pedestrian`，其余归为 `vehicle`，同时保留原细分类，后续可以单独分析骑行者。自定义二分类数据也可使用 `person / vehicle`。

每次运行创建新的输出目录，显式指定 `--output` 时该目录必须尚不存在。输出包括：

- 带框图片或 `annotated.mp4`。
- `detections.jsonl`：每张图片/每个解码视频帧一行，包括没有目标的帧。
- `summary.json`：处理帧数、各类检测框数量、配置及处理速率。视频中的检测框总数不代表独立目标数量。

逐帧结构包含 `source`、从 0 开始的 `frame_index`、`timestamp_s`、`timestamp_source`、原图宽高，以及每个目标的 `class_id / class_name / category / confidence / bbox_xyxy / track_id`。`bbox_xyxy` 是原图像素坐标，`track_id` 当前为 null；不会把逐帧检测框编号冒充跟踪 ID。

独立图片的时间戳为 null。视频优先记录解码时间戳，缺失时使用 FPS 估计并标记 `fps_estimate`；`--fps` 可显式覆盖为固定帧率。导出 MP4 使用固定帧率，后续运动分析以 JSONL 中的源时间戳为准。当前入口不包含摄像头或网络流接入。

## 什么时候需要你的数据集

预训练模型检测演示不需要先提供数据。要达到课题场景的训练、准确率评估和难例改进，就需要带边界框标注的数据集。

建议优先提供与你的演示一致的真实道路视频或图片，以及相应标注。没有现成数据时，可先从 COCO 的行人车辆类别构建基线；若场景为车载道路视频，可考虑 BDD100K，再转换为下面的格式。当前验证用的 COCO128 小样本只证明流程能执行，不足以代表课题效果。

推荐目录：

```text
data/traffic/
  images/train/000001.jpg
  images/val/000101.jpg
  images/test/000201.jpg
  labels/train/000001.txt
  labels/val/000101.txt
  labels/test/000201.txt
```

每个 txt 与图片同名，每个目标占一行，5 列用空格分隔：

```text
class_id x_center y_center width height
0 0.50 0.45 0.10 0.30
2 0.70 0.60 0.25 0.20
```

第一行的列名只是说明，不要写入标签文件。坐标全部相对原图宽高归一化到 0～1，类别 ID 必须对应 YAML 中的 names。没有目标的图片也需要空 txt，防止漏标文件被误当成负样本。

默认六类映射为 `0 person / 1 bicycle / 2 car / 3 motorcycle / 4 bus / 5 truck`。这与 COCO 原始 ID 不同：COCO 的 bus 是 5，truck 是 7，转换数据时必须重新映射。也可以仅标 `person / vehicle` 两类，但不能混用二分类和六分类标签。

从 `configs/traffic.example.yaml` 复制配置并修改 path。相对 path 按 YAML 所在目录解析；train/val/test 按 path 解析。当前训练入口支持本地图片目录，暂不接收 COCO JSON、BDD JSON、图片清单 txt 或自动下载脚本。

同一视频的相邻帧应放入同一数据划分，尽量按视频、时间段或摄像机划分训练/验证/测试，避免随机拆帧导致泄漏。程序能检查相同文件路径的重叠，复制的重复帧和同一视频的相邻帧仍需在准备数据时排除。

## 训练与评估

```bash
# 正式训练示例：GPU 0；无 GPU 时换 --device cpu，先用小规模样本
python -m detection train --data configs/traffic.example.yaml \
  --epochs 50 --batch 8 --imgsz 640 --device 0

# 用训练生成的权重验证或测试；将路径替换为实际输出目录
python -m detection val --data configs/traffic.example.yaml \
  --weights runs/yolo/train/run-xxxx/weights/best.pt --split val --device cpu

python -m detection val --data configs/traffic.example.yaml \
  --weights runs/yolo/train/run-xxxx/weights/best.pt --split test --device cpu

python -m detection detect --source data/your_video.mp4 \
  --weights runs/yolo/train/run-xxxx/weights/best.pt --device cpu

python -m unittest discover -s tests -v
```

训练前检查标签格式、类别范围、缺少标签和 train/val 路径重叠。训练输出 best.pt、last.pt、Ultralytics 日志及 `metrics.json`；独立评估也输出 `metrics.json`，包括 Precision、Recall、mAP50、mAP50-95 和有标注类别的分项指标。验证集用于调参，测试集用于最终报告，不能反复用测试集选阈值。

评估入口要求权重 names 与数据集 names 完全一致，避免把 COCO 的第 4 类与自定义第 4 类混为一谈。YOLO 的检测头会在 80 类改为自定义类别时调整，少量数据、单轮训练后的分数不能用作最终成绩。

## 后续对齐重点

1. 用你的场景建立固定数据划分，统计类别数量、小目标、遮挡、夜间和密集场景。
2. 训练 YOLOv8n 基线，记录各类指标、漏检图和误检图，再对比 YOLOv8s；先依据结果决定是否改模型。
3. 为 ByteTrack 保留较低置信度的候选框并与跟踪阈值一起调试，不能先把全部低分框过滤掉；类别细分和统一语义要贯穿训练、推理和跟踪。
4. 进入 TTC 前明确固定机位还是车载机位。像素位移不是 m/s，Kalman 的预测速度也不自动成为真实车速；需要地面标定、尺度/深度及必要的自车运动补偿。
5. 对沿同一路径接近的目标，TTC 可由距离和接近速度估计；路口横穿等场景还需判断轨迹是否冲突、最近接近时刻与距离。不能直接用任意两框的像素距离除以像素速度作为通用碰撞决策。
